# دراسة المشروع: تحويل NAAS-Agentic-Core إلى محرك إيراد بالعملة الصعبة

**التاريخ:** 25 سبتمبر 2026  
**الحالة:** دراسة استراتيجية قابلة للمراجعة — ليست رأيًا قانونيًا أو ضريبيًا  
**نطاقها:** الأدوات الموجودة في `tools/hard_currency_engine/` والوثائق المرتبطة بها.

---

## 1. الخلاصة التنفيذية

المشروع لا ينبغي أن يحقق العملة الصعبة عبر تجارة سلع مدعومة أو عبر نقل بضائع بين الجزائر وتونس. ذلك نموذج مادي، ثقيل، عالي المخاطر وقليل القابلية للتوسع. الأصل الحقيقي في هذا المستودع هو **تصدير خدمات رقمية قابلة للفحص والتسليم عن بعد**.

أفضل عرض أولي هو:

> **تدقيق وإصلاح بيانات الفوترة والامتثال للشركات الأوروبية، مع تقارير قابلة للإثبات وملفات مخرجات جاهزة للاستخدام.**

ويُباع هذا العرض ضمن أربعة مسارات موجودة فعليًا في الكود:

1. تدقيق بيانات الشركات الفرنسية والبلجيكية.
2. فحص/حساب CBAM للمستوردين الصناعيين.
3. فحص سلاسل فواتير ZATCA للشركات السعودية.
4. تدقيق الوصول الرقمي EAA، إضافة إلى تقييمات الذكاء الاصطناعي متعددة اللغات.

**الحكم الاستثماري:** توجد نواة تقنية قابلة للبيع، لكن المستودع لا يثبت وحده وجود منتج تجاري مكتمل أو امتثال قانوني مكتمل. يجب الفصل بين `CODE_CAPABILITY` و`MARKET_PROOF` و`LEGAL_READINESS` و`PAID_PROOF`.

## 2. ما الذي يملكه المستودع فعلًا؟

### 2.1 الأدوات القابلة للتغليف التجاري

| المكوّن | الوظيفة | العميل المحتمل | المخرج القابل للبيع |
|---|---|---|---|
| `france_validator.py` | فحص بيانات فرنسية | مكتب محاسبة/شركة فرنسية | تقرير + CSV منظف |
| `belgium_validator.py` | فحص بيانات بلجيكية وPeppol | مكتب محاسبة/شركة SaaS | تقرير + CSV منظف |
| `cbam_calculator.py` | حساب CBAM وحساسية التكلفة | مستورد صناعي/مستشار جمارك | تقرير مالي + XML |
| `zatca_validator.py` | فحص سلسلة الفواتير وTLV/UBL | شركة سعودية/مزود ERP | تقرير أخطاء + إصلاح |
| `eaa_scanner.py` | فحص الوصول الرقمي | متجر إلكتروني/وكالة | تقرير + بيان وصول |
| `crm_dispatcher.py` | تخصيص حملات B2B | فريق مبيعات داخلي | رسائل مخصصة وسجل حملة |

الواجهة الموحدة هي `tools/hard_currency_engine/cli.py`. وجود أمر CLI لا يساوي وجود خدمة SaaS؛ يلزم بناء طبقة آمنة لاستقبال الملفات، إدارة العملاء، التحكم في الوصول، حذف البيانات، الفوترة، وسجل الأدلة.

### 2.2 ما لا يثبته الكود

لا يثبت الكود وحده:

- أن نتيجة الفحص صحيحة قانونيًا في كل حالة.
- أن العميل سيتجنب غرامة محددة.
- أن كل قاعدة تنظيمية محدثة.
- أن البيانات المرسلة آمنة تجاريًا.
- أن القنوات المالية متاحة أو مناسبة للكيان القانوني.
- أن هناك عميلًا مستعدًا للدفع.

لذلك لا تُستخدم عبارات مثل **"تجنب غرامة مؤكدة"** أو **"امتثال مضمون"** قبل مراجعة بشرية ومصدر أولي حديث.

## 3. الفرضية التجارية

### الفرضية

شركات صغيرة ومتوسطة في أوروبا والخليج تملك ملفات فواتير أو عملاء غير نظيفة، ولا تريد توظيف مهندس امتثال بدوام كامل. يدفع العميل مقابل:

- اكتشاف الخطأ.
- تفسير أثره.
- إصلاح عينة قابلة للتحقق.
- تسليم ملف مخرجات.
- تشغيل دوري يمنع عودة الخطأ.

### وحدة القيمة

لا نبيع «ذكاء اصطناعيًا» مجردًا؛ نبيع:

```text
ملف العميل الخام
→ قواعد تحقق حتمية
→ قائمة أخطاء مصنفة
→ ملف مصحح أو مخرجات جاهزة
→ سجل أدلة وإصدار القواعد
→ مراجعة بشرية
```

### الشرط الحاكم

لا تُحتسب الصفقة نجاحًا إلا إذا نتج عنها:

1. عقد واضح.
2. تسليم قابل لإعادة التشغيل.
3. فاتورة قانونية.
4. دفع موثق من عميل خارج الجزائر.
5. ملف أدلة يحفظ ما عولج وما لم يعالج.

## 4. ترتيب فرص السوق

### المسار الأول: تنظيف بيانات الفوترة الفرنسية والبلجيكية

**الأفضل كبداية** لأنه منخفض التعقيد نسبيًا ويمكن إثباته بعينة صغيرة. العميل الأول ليس بالضرورة المؤسسة النهائية؛ مكتب محاسبة واحد قد يفتح عشرات الملفات.

**العرض:** فحص 20–50 سجلًا خلال 24–48 ساعة، ثم معالجة قاعدة أكبر.

**مخاطر يجب ضبطها:**

- لا تُرسل بيانات شخصية إلى بيئة غير مصرح بها.
- لا تدّع أن التحقق البرمجي بديل عن المحاسب أو المستشار القانوني.
- يجب تسجيل مصدر كل قاعدة وتاريخها.

### المسار الثاني: CBAM

القيمة المحتملة أعلى لأن الخطأ قد يؤثر في تكلفة الاستيراد، لكن المسؤولية أعلى أيضًا. يجب ألا تعرض الأداة نفسها كممثل جمركي أو مستشار قانوني إلا بترخيص مناسب.

**العرض المناسب:** حاسبة وسجل تدقيق أولي، لا ضمان ضريبي.

### المسار الثالث: ZATCA

السوق واضح، لكن يجب اختبار دقة XML وTLV والتوقيع وسلسلة الهاش على عينات حقيقية، وبناء شراكة مع مختص سعودي قبل بيع وعد امتثال شامل.

### المسار الرابع: EAA

قابل للبيع كفحص تقني، لكن عبارة «تجنب غرامة بقيمة محددة» لا تُستخدم كحقيقة عامة؛ تختلف المسؤولية حسب الدولة والقطاع وتطبيق القانون.

### المسار الخامس: تقييم نماذج الذكاء الاصطناعي

قابلية السوق مرتفعة، لكنه يحتاج إلى ملف أعمال، اختبارات معيارية، اتفاقيات سرية، وسياسة عدم استخدام بيانات العميل في التدريب.

## 5. عروض قابلة للبيع

### عرض A — Pilot

- 20–50 سجلًا أو فاتورة.
- تقرير أخطاء.
- عينة إصلاح.
- جلسة شرح.
- لا ضمان قانوني.
- هدفه الحصول على أول شهادة ومرجع.

### عرض B — Remediation

- قاعدة أكبر.
- معالجة آلية + مراجعة بشرية.
- ملف قبل/بعد.
- تقرير تغييرات.
- تسليم مرحلي.

### عرض C — Monitoring

- فحص دوري شهري.
- مقارنة الانحرافات.
- سجل قواعد وإصدارات.
- تنبيه عند ظهور أخطاء جديدة.

### عرض D — On-premise

- تشغيل داخل بيئة العميل.
- لا تغادر البيانات نظامه.
- رسوم إعداد + ترخيص أو دعم سنوي.
- مناسب للبيانات الحساسة.

## 6. نموذج الإيرادات والتكلفة

### الإيراد الصافي للصفقة

```text
الإيراد الصافي = سعر العقد
                 - عمولة منصة البيع
                 - تكلفة الدفع والتحويل
                 - تكلفة الحوسبة والتخزين
                 - ساعات التنفيذ والمراجعة
                 - دعم ما بعد التسليم
                 - تكلفة اكتساب العميل
                 - احتياط النزاع/الاسترجاع
                 - الضرائب والامتثال
```

### مثال تخطيطي فقط

| العرض | السعر الافتراضي | التكلفة المباشرة الافتراضية | المساهمة قبل المصاريف الثابتة |
|---|---:|---:|---:|
| Pilot | 0–250 EUR | وقت المؤسس | هدفه الدليل لا الربح |
| Remediation صغير | 500–1,500 EUR | 20–40% | متوسطة |
| ملف CBAM | 1,500–5,000 EUR | 25–45% | مرتفعة لكن عالية المخاطر |
| Monitoring شهري | 300–1,500 EUR | 15–35% | متكرر |
| On-premise | حسب النطاق | 30–60% | مرتفع بعد التثبيت |

هذه **ليست أسعار سوق مثبتة**؛ هي نطاقات داخلية لبناء اختبار، ويجب استبدالها بعروض حقيقية من العملاء. لا تُدرج في مواد التسويق على أنها أسعار قياسية.

### نقطة التعادل

```text
عدد الصفقات الشهرية = المصاريف الثابتة الشهرية / المساهمة الصافية للصفقة
```

مثال: إذا كانت المصاريف الثابتة 1,000 EUR، والمساهمة الصافية من الصفقة 400 EUR، فالنقطة التقريبية ثلاثة عقود شهريًا، لا عقدان، بسبب التقريب واحتياط عدم التحصيل.

## 7. استراتيجية الوصول إلى العملة الصعبة

### القناة التجارية

```text
دليل عميل مؤهل
→ رسالة شخصية غير مزعجة
→ عينة آمنة ومنزوعة الهوية
→ Pilot مدفوع أو محدود
→ عقد تنفيذ
→ فاتورة
→ تسليم وأثر تدقيق
→ تحصيل مصرفي موثق
→ طلب إحالة أو عقد مراقبة
```

`crm_dispatcher.py` يساعد في تخصيص الرسالة، لكنه لا ينبغي أن يتحول إلى إرسال جماعي عشوائي. يجب إضافة:

- مصدر قانوني للجهة المستهدفة.
- سجل موافقة/اعتراض.
- حد إرسال.
- إيقاف تلقائي.
- عدم تخزين بيانات شخصية غير لازمة.
- قالب بالعربية/الفرنسية/الإنجليزية.

### الأسواق الأولى

1. فرنسا: مكاتب المحاسبة ومزودو حلول الفوترة.
2. بلجيكا: شركات Peppol ومقدمو خدمات ERP.
3. الخليج: شراكات مع مزودي ZATCA وERP، لا مبيعات امتثال مباشرة قبل التحقق.
4. مستوردو المعادن والأسمنت والمواد المشمولة بـCBAM.

## 8. الحوكمة القانونية والمالية

وثيقة `docs/FOREIGN_CURRENCY_DOCTRINE.md` تضع العملة الصعبة من عميل مؤسسي خارج الجزائر كشرط للمسار. لكنها تحتوي أيضًا على ادعاءات تنظيمية متغيرة وبعض الإسناد الثانوي؛ لذلك لا يجوز تحويلها إلى نصيحة نهائية دون تحقق من:

- بنك الجزائر.
- البنك الذي سيتم فيه توطين الإيرادات.
- الضرائب.
- قانون المقاول الذاتي أو الشركة المختارة.
- قواعد حماية البيانات في بلد العميل.
- شروط المنصة المالية المستخدمة.

### قواعد تشغيلية غير قابلة للتفاوض

- لا حسابات شخصية لاستلام أموال العميل.
- لا عملات مشفرة كبديل عن القناة المصرفية إذا كانت مخالفة للقانون المحلي.
- لا إخفاء للعميل أو مصدر الإيراد.
- لا ادعاء بإعفاء ضريبي دون وثيقة نافذة.
- لا تسليم لبيانات عميل حقيقية إلى نموذج لغوي دون أساس تعاقدي وموافقة.
- لا تخزين دائم لملفات العميل الخام.
- كل فاتورة تحمل نطاق الخدمة، تاريخها، وعملة الدفع.

### مصفوفة الأدلة

كل ادعاء قانوني أو مالي في وثائق المشروع يجب أن يحمل:

```text
CLAIM_ID
المصدر الأولي
تاريخ النفاذ
تاريخ آخر تحقق
النطاق الجغرافي
درجة الثقة
مالك المراجعة
تاريخ المراجعة القادمة
```

وعند تعارض مصدر ثانوي مع نص رسمي، يُوسم الادعاء `OPEN` ولا يُستخدم في عقد أو إعلان.

## 9. أمن البيانات

المنتج يتعامل مع ملفات قد تحتوي على بيانات شخصية وتجارية حساسة. قبل أول عميل يجب تنفيذ الحد الأدنى الآتي:

- تشفير النقل والتخزين.
- عزل كل عميل عن الآخر.
- حذف تلقائي بعد فترة محددة.
- سجل وصول غير قابل للتلاعب.
- عدم طباعة محتوى الملف في logs.
- فحص الملفات ضد malware.
- تحديد أنواع الملفات المقبولة وحجمها.
- سياسة احتفاظ وحذف معلنة.
- اتفاق NDA وDPA عند الحاجة.
- مسار On-premise للبيانات عالية الحساسية.

**ملاحظة تقنية:** واجهة CLI الحالية مناسبة للاختبار المحلي، وليست بوابة استقبال إنتاجية. لا تُفتح مباشرة على الإنترنت قبل بناء طبقة API ومصادقة ورفع ملفات آمن.

## 10. خطة تنفيذ 90 يومًا

### الأيام 1–15: إثبات القدرة

- تثبيت اختبارات الوحدات لكل validator.
- إنشاء عينات مجهولة المصدر.
- تحديد قواعد الإصدار والتاريخ.
- إنتاج تقرير موحد باللغة الفرنسية.
- حذف الادعاءات غير المسندة من التسويق.

### الأيام 16–30: إثبات الطلب

- بناء قائمة 50 جهة مستهدفة.
- إرسال رسائل شخصية محدودة.
- إجراء 10 مقابلات.
- الحصول على 3 ملفات تجريبية منزوعة الهوية.
- قياس: الرد، طلب العينة، قبول العرض، الاعتراضات.

### الأيام 31–45: أول Pilot

- تنفيذ Pilot واحد على الأقل.
- توثيق الفرق قبل/بعد.
- مراجعة بشرية للمخرجات.
- تحديد زمن التنفيذ وتكلفته.
- إعداد نموذج عقد وفاتورة.

### الأيام 46–60: المنتج القابل للتسليم

- حزمة تقرير موحدة.
- سجل أدلة.
- صفحة عرض.
- تسعير اختباري.
- قناة دفع قانونية مؤكدة مع البنك/المحاسب.

### الأيام 61–90: التكرار والتوسع

- تحويل Pilot إلى عقد مدفوع.
- بيع خدمة مراقبة شهرية.
- توقيع شريك واحد على الأقل.
- إضافة بوابة ملفات آمنة أو تسليم On-premise.
- إصدار تقرير KPI شهري.

## 11. مؤشرات الحكم على نجاح المشروع

### مؤشرات تجارية

- عدد العملاء المؤهلين.
- معدل الرد.
- معدل قبول العينة.
- معدل تحويل Pilot إلى عقد.
- متوسط قيمة العقد باليورو.
- نسبة العقود المتكررة.
- زمن التحصيل.
- تكلفة اكتساب العميل.

### مؤشرات تقنية

- دقة القاعدة على مجموعة مرجعية.
- معدل الإيجابيات الكاذبة.
- معدل فشل parser.
- قابلية إعادة إنتاج التقرير.
- زمن المعالجة لكل 1,000 سجل.
- نسبة المخرجات التي راجعها إنسان.

### مؤشرات العملة الصعبة

- الإيراد المدفوع فعليًا، لا المتعاقد عليه فقط.
- العملة، تاريخ الدفع، مصدره، وقناة وصوله.
- رسوم التحويل.
- مدة الترحيل المصرفي.
- نسبة الإيراد خارج الجزائر إلى إجمالي الإيراد.

## 12. المخاطر وطرق تخفيفها

| الخطر | الأثر | التخفيف |
|---|---:|---|
| قاعدة قانونية قديمة | مرتفع | سجل مصدر/نفاذ ومراجعة ربع سنوية |
| وعد قانوني مبالغ فيه | مرتفع | تسويق «فحص تقني» لا «ضمان امتثال» |
| تسرب بيانات | مرتفع جدًا | عزل وتشفير وحذف وOn-premise |
| عدم دقة المخرجات | مرتفع | مجموعة اختبار + مراجعة بشرية |
| عميل لا يدفع | مرتفع | Pilot مدفوع/دفعة مقدمة/منصة موثوقة |
| الاعتماد على منصة واحدة | متوسط | قنوات دفع مؤسسية بديلة قانونية |
| إرسال تسويقي مزعج | متوسط | قائمة منشأ مشروع وحدود وتسجيل اعتراض |
| اعتماد المنتج على المؤسس | مرتفع | توثيق وتشغيل آلي وSOP |
| اختلاف قوانين البلد | مرتفع | شريك محلي ومراجعة مختص |

## 13. قرار go / no-go

### Go إذا تحقق الآتي

- ثلاث عينات حقيقية منزوعة الهوية تعمل بنجاح.
- عميل واحد على الأقل يدفع مقابل Pilot.
- تقرير قابل لإعادة الإنتاج.
- قناة تحصيل مؤسسية موثقة.
- مراجعة قانونية أساسية للعقد والبيانات.
- تكلفة التنفيذ أقل بوضوح من سعر البيع.

### No-go أو توقف مؤقت إذا

- لا توجد عينة صحيحة يمكن اختبارها.
- لا يستطيع المشروع إثبات مصدر النتيجة.
- التسويق يعتمد على تخويف العميل من غرامة غير مؤكدة.
- لا توجد قناة تحصيل قانونية للكيان.
- تُرفع بيانات شخصية حقيقية إلى أدوات غير مضبوطة.
- كل الطلبات تأتي من أفراد لا من عملاء مؤسسيين خارج الجزائر.

## 14. التوصية النهائية

المشروع الأنسب للمستودع هو **شركة تصدير خدمات برمجية وامتثال بيانات**، لا تجارة سلع. يبدأ المنتج من الأدوات الموجودة، لكن نجاحه يتطلب إضافة طبقة تجارية وأمنية وقانونية حولها.

الأولوية العملية:

1. اختيار `france_validator` و`belgium_validator` كعرض أول.
2. استعمال `cbam_calculator` كعرض متخصص أعلى قيمة بعد تثبيت دقته.
3. تحويل `crm_dispatcher` إلى مبيعات B2B منضبطة، لا إرسال جماعي.
4. إبقاء ZATCA وEAA ضمن عروض تجريبية إلى أن تُراجع القواعد والشراكات.
5. إنشاء سجل `PAID_PROOF` يفرق بين القدرة التقنية والمال المحصل فعليًا.
6. مراجعة عقيدة العملة الصعبة ومصادرها قبل اعتماد أي رقم قانوني أو ضريبي.

**المعيار الحقيقي للنجاح ليس أن يحتوي المستودع على أدوات كثيرة، بل أن يمر المسار كاملًا مرة واحدة:**

```text
مشكلة عميل أجنبي
→ عينة مجهولة
→ نتيجة قابلة للتحقق
→ عقد
→ فاتورة باليورو/الدولار
→ تسليم آمن
→ دفع مؤسسي موثق
→ عقد متكرر
```

هذا هو المسار الذي يحول `NAAS-Agentic-Core` من مستودع أدوات ووثائق إلى مشروع فعلي مولّد للعملة الصعبة.
